【六、内容数据模型】

实现强类型 schema 和构建验证，至少支持：

Game：id、name、slug、aliases、platforms、officialUrls、description、currentVersion（可空）、coverageStatus、maintenancePriority、image（可选且有来源/许可）。

Article：id、gameId、type（codes/guide/event/update）、slug、title、summary、authorId、body、publicationStatus（draft/review/published/archived）、freshnessStatus（current/due/outdated/maintenance_paused）、publishedAt、updatedAt、lastReviewedAt、nextReviewAt、gameVersion、sourceIds、changeSummary、seo。发布日期和未来事件时间必须分开；发布时间不能由构建时间自动重置。

Code：id、gameId、code、reward、conditions、region/server/version（可空）、status、officialStatus、testStatus、discoveredAt、lastReviewedAt、sourceIds。状态允许 official_active、tested_working、reported_expired、unknown，并明确说明是官方发布、编辑亲测还是待核验。不把官方发布等同于亲测成功；没有账号/证据时禁止显示 tested。

Event：id、gameId、slug、name、startsAt/endsAt（可空）、datePrecision、sourceTimezone、region/server、eligibility、rewards、status、sourceIds、lastReviewedAt。时间存 ISO UTC；只有日期时保留 date-only 精度，不能默认填零点误导。展示用户本地时间时同时保留原时区或 UTC。日期未知不要倒计时。

Source：id、url、publisher、sourceType、accessedAt、supports、verificationMethod、notes。只存必要摘要和自主结论；不存付费源全文。HTTP 200 只是链接检查，不能自动把内容改成 verified。

Author：真实 id、名称、简介、实际职责；没有真人实玩团队时用诚实的 Rulevio Editorial，不虚构玩家资历。

Opportunity：id、keyword、discoveredAt、sourceReference、gameId（可空）、intent、aliases、targetContentId、suggestedCanonical、scoreBreakdown、status、nextAction、owner、nextReviewAt。status 至少含 discovered/researched/qualified/planned/drafting/published/measuring/stopped/blocked。这里的 blocked 是候选内容状态，不是工程可以停止的理由。

Revision/Review：contentId、reviewedAt、reviewMethod、changedFields、summary、operatorType、nextReviewAt。核验无变化只更新 lastReviewedAt；有实质变化才更新 updatedAt。单一代码/事件数据被多个模板引用时只维护一次。

验证包括：引用存在、slug/ID 唯一、code 去重、时间顺序合法、未来 publishedAt 不误公开、草稿不进入列表/搜索/sitemap/RSS/推荐、来源完整、无假作者、无假测验状态。时间逻辑封装为可注入 now 的纯函数，便于跨时区测试。

【七、四类模板与玩家交互】

1. Codes：首屏代码表、奖励、状态、适用条件、来源和最后核验说明；复制按钮有动态成功与失败反馈；过期与未知分区；兑换步骤、失败排错、官方入口、更新记录。复制成功不是兑换成功，不能自动改变 code 状态。
2. Guide：简明答案、版本/前提、材料和步骤、必要分支、排错、来源和相关指南。步骤支持本地勾选，按 articleId + revision/version 保存；文章大改要提示重新核对，避免旧完成进度误应用。
3. Event：起止时间、当前状态、地区/服务器、参与条件、奖励、来源；明确时间才允许倒计时和 ICS 导出。已经结束显示 Ended，不能无限倒计时到负数；日期精度不足时拒绝导出错误的精确时间。
4. Update：补丁或公告摘要、变化、玩家下一步、受影响指南和官方原文。小变更优先更新已有页，不把每条公告都扩成新薄页。

收藏/关注：首版 localStorage，无需账号；/following/ 聚合本地关注游戏和收藏页，显示本地保存说明、取消和清空。存储不可用时优雅退化，不阻塞正文。没有后端时不要显示跨设备同步或邮件已订阅成功。

搜索：采用适合静态内容的本地搜索索引，支持游戏名、别名、标题和类型；草稿不入索引。搜索结果提供用途和游戏；查询参数不生成可索引页面。输入不能导致 XSS。

【八、本地内容工作台】

这是第一阶段的核心交付之一。为站主提供浏览器表单，避免日常需要手写 frontmatter：

- 候选机会导入与编辑：支持粘贴关键词和简单 JSON/CSV；预览导入、去重、游戏匹配、关联已有页。
- 内容列表：按游戏、类型、发布状态、新鲜度过滤。
- 表单编辑游戏、文章、代码、活动、来源，支持 Markdown 预览、schema 错误定位、保存草稿。
- 复核队列：到期原因、当前来源、复核方法、是否变化、下一次检查时间。
- 保存前差异预览；发布前运行验证；明确区分保存、标记待发布、实际部署。
- 显示最后内容修改与最后复核两个时间。

工作台只在本地开发模式运行，不得暴露生产写入能力。写入服务仅绑定 loopback，检查 origin/CSRF，限定到内容目录，阻止路径穿越、符号链接逃逸和并发覆盖，采用原子写入与版本冲突检查。不接受任意命令或任意文件路径。生产构建排除工作台和写入 API。

同一套 schema、校验器和数据读取供站点、CLI、工作台共用。若当前环境无法完成工作台的部分功能，先提供真实可用 CLI 并明确剩余任务，不能把只有静态界面的工作台宣称完成。

【九、新词工作流和维护报告】

Web.Cafe 仅用于发现关键词。支持手动粘贴/授权导出，不绕过登录，不抓取付费全文，不假设存在 API，不镜像付费数据库。即使以后接入 API，也只影响机会入口，不影响内容 schema。

流程：发现 → 确认游戏/玩家意图 → 去重/关联已有页 → 公开研究 → 排序 → 创建或更新草稿 → 编辑审核 → 发布 → 指标复盘 → 复核/停止维护。

评分权重为玩家需求25、现有主题匹配20、更好答案空间20、资料可靠性15、持续价值10、维护成本10。score 是内部决策，不显示给玩家，不伪造搜索量。无法确认游戏实体和核心事实时保持候选状态。

【十一、SEO、设计和内容质量】

- 页面可抓取，title/description/canonical 独立且准确；sitemap/RSS/搜索索引只含适合公开的发布内容。
- Article、BreadcrumbList、Organization 标记与可见内容一致。无虚假评分；无虚构 FAQ 富结果承诺。
- 内链以同游戏、同任务和自然关联为依据，不全站机械互链。
- 日期与版本真实，不因构建每天刷新 updatedAt。
- 空分类、内部搜索、筛选参数、工作台和个人计划不索引；不要误 noindex 所有生产正文。
- 不能直接搬运其他攻略站的文字、截图或数据库。AI 可帮助整理研究和草稿，不自动把大量低价值页面推向生产。
- 视觉采用高可读性的游戏出版物风格：清楚字体层级、适中正文宽度、轻量卡片、精简导航。不要做后台式首页或满屏 neon 玻璃卡片。
- 先保证移动端阅读与复制：360/390px、桌面、键盘和200%缩放可用；TOC不挡正文，表格有可访问的响应式处理。
- 图片为有授权来源或原创，提供尺寸和 alt，懒加载非首屏图片。无可用图片时用清晰排版，不制造假游戏截图。
- 广告槽组件配置关闭时完全不显示；预留尺寸避免 CLS。代码复制按钮不紧贴广告，不做首屏插屏或自动播放视频。
- Contact/Corrections 无服务时给出真实现有联系渠道或明确配置说明；表单不能只在前端弹出“发送成功”。

【十四、实施顺序】

阶段A：仓库审计、转型Spec、旧URL清单、模块隔离、schema和内容读取层。
阶段B：游戏中心、四类模板、首页和列表、SEO/RSS/sitemap、Markdown渲染、真实内容草稿。
阶段C：搜索、复制、步骤勾选、本地关注、活动状态与ICS、到期报告。
阶段D：本地内容工作台、导入、预览、差异、校验和复核记录。
阶段E：实际内容研究、公开内容检查、迁移配置、测试、操作手册和预览。

不要把五个阶段理解为每完成一个都停下来询问。连续完成第一阶段产品所需的A到E；依赖外部密钥的newsletter/analytics/广告真实接入例外，保持禁用并写清后续配置。

【十五、必须可演示的验收】

1. 新增游戏和新文章只新增数据，不改路由组件；预览能正确出现并链接。
2. 修改一个代码记录，所有引用处同步；状态、来源和核验日期不丢失。
3. draft/review文章无法从生产URL访问，也不出现在sitemap、RSS、索引和推荐。
4. 公开文章主答案在禁用JS时可见。
5. 复制失败有反馈，成功后明确提示；勾选与收藏刷新可恢复，存储禁用仍能阅读。
6. 活动在未开始/进行中/结束的边界正确，日期精度和UTC/本地显示正确，ICS无需第三方账号且不导出虚假时间。
7. 复核无变化只改lastReviewedAt；真正内容修改保留revision。
8. content:report能指出人为构造的到期/失效fixture，但不会把fixture发布到生产或冒充真实核验。
9. slug重复、断引用、非法日期、错误code状态的构建失败且定位文件字段。
10. 本地工作台真实保存内容并检测并发覆盖；生产没有写入API，非法路径、CSRF和脚本注入检查通过。
11. 内链、canonical、schema、404/410/redirect语义正确；没有旧LiveOps/validator营销残留。
12. 移动端、键盘和200%缩放完成检查；广告与外部服务未配置不会出现假成功或空广告框。
13. 写清如何导入Web.Cafe候选、研究、发布一篇攻略、更新一条代码、复核一篇内容、暂停维护、构建、预览、部署和回滚。

对schema、发布过滤、状态边界、代码去重、工作台写入限制和时间/ICS做有意义的自动测试；对关键读者/编辑流程做少量浏览器测试。不要写只镜像实现的冗余测试。不能通过删旧测试或伪造输出让检查通过，旧业务测试与新站测试分开执行和报告。
