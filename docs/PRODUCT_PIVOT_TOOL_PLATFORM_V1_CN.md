# 新词驱动工具集合平台：BriefVu 产品转型基线 V2

更新日期：2026-10-14

> 2026-10-15 路由补充：本文只定义 `briefvu.com` 的独立小工具平台。AI 产品收录路由到 `aibesttool.com`，游戏内容路由到 `rulevio.com`。三站统一机会管道与第一轮清单见 `docs/THREE_SITE_KEYWORD_PIPELINE_2026-10-15_CN.md`。

## 1. 正确的产品模型

产品从“定制服装询价整理工具”转型为一个由新词机会驱动的**自营工具订阅平台**。所有工具由 BriefVu 开发并在站内产生最终结果；用户以一份订阅使用平台内全部工具。

新词订阅网站是机会发现源，不是要复制的内容站。工作流是：

> 发现新词 → 判断是否存在工具意图 → 设计最小可用工具 → 发布独立工具页 → 观察搜索与使用数据 → 保留、改进或停止

各工具之间不需要属于同一行业、同一用户或同一功能类别。平台层提供统一的发现、执行、账号、权益、订阅、质量、SEO和分析基础设施。

BriefVu 不是第三方工具收录、比较或导航站，也不以帮助用户选择、安装或使用第三方产品为核心。搜索用户应在 BriefVu 内输入任务并得到可复制、下载或保存的最终结果。

## 2. 产品边界

平台允许同时包含互不相关的工具，例如：

- 新出现的 AI 概念对应的检测器或生成器
- 社交平台新格式对应的尺寸、文本或内容工具
- 新商业术语对应的计算器、检查器或模板生成器
- 新法规、新流程或新工作方式对应的自查工具
- 新文件格式、表达方式或提示方法对应的转换器

平台不要求工具之间形成主题集群，但统一订阅必须建立在跨工具权益、重复使用或高价值处理能力之上。孤立、低频、只能导向第三方的软件选择器不能作为订阅产品核心。

## 3. 新词来源与合规原则

订阅网站只用于发现公开术语与趋势信号：

- 不复制其付费文章、解释、数据库结构或独家评分
- 不公开订阅账号、原文、截图或受限数据
- 不把对方内容批量镜像到本站
- 对新词进行独立研究，并自行设计工具、说明与示例
- 若术语涉及商标、医疗、法律、金融或高风险决策，先做风险审核

仓库只保存经过筛选后的关键词、公开来源链接、评分和自主研究结论。

## 4. 新词筛选评分

每个候选新词按 0–5 分评估：

1. **Tool intent**：用户是否会搜索 generator、checker、calculator、converter、template 或 formatter 等可执行结果。
2. **Problem clarity**：是否能用一句话定义输入和输出。
3. **Freshness advantage**：现有搜索结果是否还没有成熟工具。
4. **Buildability**：能否在 1–3 天内做出真正可用的首版。
5. **Repeatability**：是否有重复使用或传播价值。
6. **Subscription value**：批量、保存、历史、高额度、持续更新或跨工具权益是否构成真实订阅价值。
7. **Risk**：版权、商标、高风险建议、平台政策和滥用风险；风险越高扣分越多。

建议机会分：

`机会分 = 工具意图×3 + 问题清晰度×2 + 新鲜度×3 + 可构建性×2 + 复用性 + 商业化 - 风险×3`

只有工具意图不低于 3、风险不高于 2 的候选词进入开发池。

## 5. 候选词状态机

- `discovered`：从订阅源发现，尚未验证
- `researched`：完成公开搜索和意图调查
- `qualified`：通过评分，值得开发
- `planned`：输入、输出、边界和页面结构已确定
- `building`：正在开发
- `published`：工具已上线并可使用
- `measuring`：等待索引与真实使用数据
- `improving`：根据数据继续优化
- `stopped`：无需求、不可行或风险过高

任何新词都不能从 `discovered` 直接进入 `published`。

## 6. 平台信息架构

- `/`：新工具和热门工具入口
- `/tools`：全部工具目录
- `/tools/[slug]`：每个独立工具的可索引页面
- `/categories/[slug]`：当某一类别自然积累到足够工具时再创建
- `/new`：最新发布工具
- `/popular`：按匿名真实使用数据排序
- `/pricing`：一份订阅使用全部工具的权益说明
- `/account`：账号、订阅、用量和保存内容
- `/about`：说明工具选择和数据处理方式

不预先建立大量空分类。分类来自已经发布的工具，而不是用分类约束选词。

## 7. 每个工具的最低发布标准

每个工具可以采用完全不同的业务逻辑，但必须满足统一质量门槛：

- 首屏一句话说明用途
- 明确的输入、操作和输出
- 核心功能可直接试用，不以注册墙完全阻断；批量、保存、历史和高额度可作为统一 Pro 权益
- 至少一个可加载的示例
- 错误、空结果与不支持情况有明确反馈
- 结果可复制或下载，复制成功有动态反馈
- 独立 title、description、canonical、Open Graph 和结构化数据
- 页面包含原创说明、边界、FAQ 和公开研究来源
- 手机、键盘操作与 200% 缩放可用
- 记录匿名的查看、开始、成功、失败和复制事件

纯粹换标题、换提示词但输出没有独立价值的页面不算新工具。

## 8. 技术平台设计

### 可复用基础设施

- Next.js 与 Cloudflare 部署
- 工具注册表与动态路由
- 通用页面壳、输入区、结果区、复制/下载反馈
- 每个工具独立的 schema、执行器和边界规则
- API 限流、错误处理与匿名事件
- sitemap、robots、JSON-LD 和 SEO 测试
- 生产监控和工具级成功率监控

### 工具实现类型

1. **Browser-only**：计算器、格式化、转换和校验，优先本地执行。
2. **Rule-based API**：需要服务端规则或公共数据，但不需要模型。
3. **AI structured tool**：模型输出必须经过 schema 校验和错误处理。
4. **External-data tool**：调用第三方数据源，必须记录成本、授权与缓存策略。

优先选择 browser-only 和低成本工具，避免平台早期被模型调用成本拖累。

## 9. SEO 发布模型

SEO 的基本单位是一个真实可用的工具页，而不是围绕统一主题写内容集群。

每个新词发布前独立验证：

- 当前搜索结果的主导意图
- 是否已有强势免费工具
- 新词是否仍在增长或已快速消退
- 用户真正需要的输出格式
- 页面是否能提供比定义文章更直接的价值

工具之间无业务关联时，不强行互链。只展示基于类别、输入类型或真实共同使用行为的相关工具。

## 10. 商业化

核心收入模式是 BriefVu Pro：一份月付或年付订阅解锁全部工具的高额度、批量、保存、历史和后续新工具。广告、联盟和第三方导流不作为 BriefVu 的产品核心。

首个工具仍需提供真实免费试用；在工具包没有形成重复价值前，先实现权益接口而不是急于完成复杂支付系统。

## 11. 迁移路线图

### Phase 0：建立机会管道

- 确认订阅网站、访问方式和允许使用的范围
- 建立候选新词数据库与评分字段
- 导入第一批候选词，但不保存付费正文
- 选出第一个可在 1–3 天发布的工具

### Phase 1：平台骨架

- 将首页改为独立工具集合入口
- 建立 `/tools`、工具注册表和统一工具页框架
- 增加工具级匿名分析与发布检查
- 保留旧 BriefVu 页面，迁移完成前不贸然删除

### Phase 2：首批验证

- 发布 3–5 个互不相关但评分合格的工具
- 提交 sitemap 并检查索引
- 比较曝光、点击、启动、完成与复制率
- 记录每个工具从发现到发布的实际成本

### Phase 3：形成工具工厂

- 每周固定完成发现、研究、筛选、开发、发布和复盘
- 根据真实数据提高或降低某类工具的优先级
- 只自动化重复流程，不自动发布未经人工审核的页面

## 12. 首阶段成功指标

发布后 60 天观察：

- 至少评估 50 个候选新词
- 10 个进入 qualified
- 3–5 个真实工具上线
- 工具页被 Google/Bing 收录
- 至少 100 次非内部工具启动
- 单工具完成率达到 40% 以上
- 能确认至少一个工具拥有持续曝光或真实复用

流量为零时，生产系统“无错误”不代表产品得到验证。

## 13. 当前待确认输入

4. 新平台是否继续使用 BriefVu 品牌与 `briefvu.com`。
